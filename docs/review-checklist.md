# 后端代码 Review 清单

审查时按 8 类逐项过。与本次改动无关的项标注"不适用"并写明原因。

## 1. 需求对齐
- 对照 Spec，每条验收标准是否都满足
- 有无 Spec 之外自作主张加的功能（范围蔓延）
- 请求和响应字段、状态码、错误码是否与 Spec 一致

## 2. 边界与异常
- 空值、nil、空集合、空字符串、纯空白的处理
- 超长输入、非法格式、非法类型、数值溢出、除零、数组越界
- 错误是否被吞掉；错误是否带上下文包装（%w）
- 超时、重试、第三方服务返回异常的处理

## 3. 并发与幂等
- 共享数据的读写是否加锁，有无竞态（-race）
- 锁的范围是否过大或过小，有无死锁风险
- goroutine 是否可能泄漏（缺少退出条件、channel 阻塞）
- 重复请求是否产生重复数据；重试是否安全
- context 是否传递，取消和超时是否生效

## 4. 数据库
- SQL 是否拼接字符串（注入风险），是否使用参数化查询
- 查询条件、排序、关联字段是否有索引；是否会走全表扫描
- 新增索引是否合理：区分度、联合索引顺序、是否冗余、写入开销
- 是否存在 N+1 查询（循环里查库）
- 是否一次性加载全表或大结果集，是否缺少分页和 LIMIT
- 事务边界：该成组的操作是否在同一事务，事务是否过长
- 事务内是否做了远程调用或耗时操作
- 连接、Rows、事务是否正确关闭或回滚
- 表结构或数据迁移：是否可回滚、是否锁表、是否兼容新旧代码并存

## 5. 安全
- 用户输入是否校验和转义
- 接口是否缺少鉴权，是否存在越权访问他人数据
- 响应和日志是否泄露内部信息（路径、堆栈、密钥、后端地址）
- 有无硬编码密钥、密码、token
- 敏感数据（手机号、证件号）是否脱敏

## 6. 性能与健壮性
- 请求体大小限制、HTTP 服务器各类超时
- 对外调用是否设置超时，连接池参数是否合理
- 大对象、大循环、频繁内存分配
- 是否存在缓存缺失、缓存穿透、缓存与数据库不一致
- 限流、降级、熔断（涉及外部依赖时）

## 7. 可维护性
- 命名清晰、函数职责单一、嵌套不过深
- 有无重复代码或过度设计
- 是否符合 AGENTS.md 的分层和依赖约定
- 接口或数据结构变更是否兼容已有调用方
- 必要的注释是否存在，注释是否与代码一致
- 有无遗留的调试代码、无用代码

## 8. 测试与可观测性
- 有无永远通过或断言太弱的测试
- 边界、异常、并发场景是否有测试
- 失败请求是否验证了"无副作用"
- 关键路径是否有日志，日志级别是否合理，有无敏感信息
- 关键指标是否可监控，出问题能否快速定位
- 变更能否快速回滚，回滚后数据是否一致
