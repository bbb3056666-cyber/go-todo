# 创建待办 Spec

## 目标

提供 `POST /todos` 接口，创建仅包含标题的待办。无需登录，所有调用者共享同一份内存数据；进程重启后数据不保留。重复提交允许创建多条记录，不去重、不提供幂等保证。

本文件仅定义需求与验收，不包含接口实现。

## 接口定义

### 请求

- 方法与路径：`POST /todos`
- 请求体：JSON 对象，仅接收 `title` 字段。
- `title`：必填字符串。先去除首尾空白，再校验非空且长度不超过 100 个 Unicode 码点；中文字符计为 1，按码点计数而非 UTF-8 字节数。内部空白保留。
- `id`、`done`、`created_at` 由服务端生成，不接受客户端赋值。请求包含未定义字段时返回 400。

```json
{"title":"  学习 Go  "}
```

### 创建成功

HTTP 状态码为 `201 Created`，响应类型为 `application/json`。

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "id": "1",
    "title": "学习 Go",
    "done": false,
    "created_at": "2026-10-30T10:00:00Z"
  }
}
```

| 字段 | 约定 |
| --- | --- |
| `id` | 服务端生成的非空字符串，同一进程中每条待办唯一；不限定生成算法，示例值不代表固定值。 |
| `title` | 去除首尾空白后的标题。 |
| `done` | 布尔值，创建时固定为 `false`。 |
| `created_at` | 服务端生成的创建时间，字符串，符合 RFC3339；不要求特定时区偏移。 |

### 请求错误

请求体不是单个合法 JSON 对象、缺少 `title`、`title` 非字符串（含 `null`）、去除首尾空白后为空、超过 100 个码点，或包含未定义字段时，返回 `400 Bad Request`。不得写入待办数据。

响应类型为 `application/json`，统一使用以下结构：

```json
{
  "code": 400,
  "msg": "title 不能为空",
  "data": null
}
```

`code` 固定为 `400`；`msg` 说明具体请求错误，不要求固定文案；`data` 为 `null`。

## 验收标准

1. 合法标题创建成功，返回 201、`code: 0`、`msg: "ok"`，并包含全部四个数据字段。
2. 标题首尾空白被移除，内部空白保留；返回值与保存值一致。
3. 去除首尾空白后，1 个和 100 个码点的标题均可创建；101 个码点返回 400。100 个中文字符可创建。
4. 空请求体、非法 JSON、非对象 JSON、多个连续 JSON 值、缺少标题、空标题、纯空白标题，以及数字、布尔、数组、对象或 `null` 类型标题均返回 400，且不新增记录。
5. 请求携带 `done`、`id`、`created_at` 或其他未定义字段时返回 400，不新增记录。
6. 每次创建均由服务端产生唯一 ID 和可按 RFC3339 解析的创建时间，`done` 为 `false`。
7. 连续两次提交相同合法标题，均返回 201，产生两条 ID 不同的记录。
8. 不同调用者共享内存数据；并发创建不产生重复 ID 或数据竞争。
9. 实现须遵守 AGENTS.md 中的目录分层、依赖和错误处理约定

## 范围外

- 描述、截止时间及其时区或过去时间校验。
- 登录、用户隔离和权限管理。
- 去重与幂等处理。
- 数据库和持久化。
- 分页、查询、修改、删除接口。
- 接受客户端指定完成状态、ID 或创建时间。

## 验证方式

- 实现阶段使用与源文件同目录的表驱动单元测试，覆盖上述成功、校验边界、请求错误、重复提交及服务端默认值。
- 通过 HTTP 测试校验状态码、JSON 包装、响应字段及 RFC3339 时间；通过 service/store 测试确认写入内容、错误请求无写入及并发安全，无需增加查询接口辅助验收。
- 实现后启动服务，对 `POST /todos` 提交合法与非法 JSON，核对响应。
- 完成工作后运行 `make check`，执行格式化、`go vet ./...` 和 `go test ./... -race -cover`，并报告实际结果。
